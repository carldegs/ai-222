1. An LLM is a prediction system built from text

The introduction showed what language models can do. This lecture opens the pipeline: collect text, convert it into token IDs, turn those IDs into vectors, and train a model to predict tokens. Each choice changes what the model can represent and how much computation it needs.

Data

Examples the model learns from. Quantity matters, but source, quality, and representation matter too.

Tokenizer

A repeatable conversion between text and a sequence of discrete tokens or token IDs.

Model

A system that maps token context to useful representations or a probability distribution for a prediction.

P(x₁, …, xL) = P(x₁) P(x₂ | x₁) ··· P(xL | x₁, …, xL₋₁)
\[p(x_1,\ldots,x_L)=\prod_{t=1}^{L}p(x_t\mid x_1,\ldots,x_{t-1})\]

This is the chain rule: the probability of an entire token sequence can be broken into next-token predictions. A prompt supplies the earlier tokens; a decoder-style model predicts the continuation one token at a time. The equation is about tokens, not raw characters.

Essay move: Describe the pipeline in order: source text → tokens → token IDs → vectors → sequence model → output. Say where the prompt enters when explaining generation.

2. What text is the model learning from?

Web text is large and varied, so it is a useful starting point. But web users and contributors are not a balanced sample of all people, languages, or topics. Filtering and deduplication can improve a corpus while also changing which voices survive. The lecture names WebText, C4, GPT-3’s mixture, and The Pile as examples of different collection strategies.

Text becomes numbers

3. Tokenization defines the model’s reading units

A tokenizer breaks a string into units, then maps each unit to an integer ID. In the lecture’s simple example, “the cat sat on the mat” becomes six word tokens and IDs [0, 1, 2, 3, 0, 4]. The repeated ID 0 represents the repeated word “the.” Real systems often use subwords or bytes so uncommon words and many scripts remain expressible.

Coverage

Can it handle the needed languages, symbols, numbers, code, and unseen words?

Efficiency

How many tokens does a typical input become? More tokens mean more sequence positions to process.

Reversibility

Can the original text be reconstructed, including spaces and punctuation? The lecture highlights this for SentencePiece.

Common trap: One word is not always one token. A common word may be one token, while an uncommon word may split into pieces. Token IDs are lookup labels, not numerical meanings.
Light computation

4. Walk through a tiny byte-pair merge

Byte Pair Encoding (BPE) starts with small units and repeatedly merges a frequent adjacent pair. The lecture’s toy corpus is “the cat,” “the cap,” “the bat.” Click through the illustrative merge order to see why common pieces become tokens. Ties can be resolved differently in a full tokenizer.

Watch the vocabulary grow

Start: Each letter is a unit. In the three “the” prefixes, the adjacent pair t+h occurs three times.
thecat

For one target string, “the cat,” the selected merges reduce its six letter units to [the, ca, t]. This shows how a learned vocabulary compresses frequent patterns into fewer positions. It does not mean the token “the” has been assigned a semantic meaning by the merge algorithm.

Compute it: If a sentence uses 9 tokens under one tokenizer and 4 under another, the reduction is (9 − 4) / 9 = 55.6%\((9-4)/9\approx55.6\%\) fewer tokens for that sentence. Do not generalize that percentage to every sentence.
IDs become features

5. Embeddings turn discrete tokens into vectors

An ID such as 0 or 4 is just an index. An embedding table uses that index to retrieve a learned vector. If a sequence has L\(L\) tokens and each vector has d\(d\) features, the resulting array has shape L × d\(L\times d\) when tokens are written as rows.

ID sequence: [0, 1, 0] Embedding lookup: [E₀, E₁, E₀] If E has |V| rows and d columns, output shape = 3 × d.
\[E\in\mathbb{R}^{|\mathcal V|\times d},\qquad [0,1,0]\mapsto[E_0,E_1,E_0]\in\mathbb{R}^{3\times d}\]

The same ID starts with the same lookup vector. A contextual representation is different: after the sequence model processes surrounding words, the vector for a position can depend on the sentence. Thus “bank” can represent a financial institution in one sentence and a riverbank in another.

Shape check: With a vocabulary of 5,000 tokens and dimension d = 128\(d=128\), an embedding table has 5,000 × 128 = 640,000\(5{,}000\times128=640{,}000\) scalar entries. A 6-token input produces a 6 × 128\(6\times128\) embedding array before later model operations.
Choose the architecture by task

6. Encoder, decoder, or both?

The lecture groups language models by which Transformer components they use. This is a useful exam comparison: ask what context a position may read and whether the task needs a new output sequence.

FamilyTypical access and outputGood example
Encoder only (BERT)Uses both sides of an available input for contextual understanding; commonly trained with masked-token objectives.Classify sentiment or compare two statements.
Decoder only (GPT)Uses earlier tokens when predicting the next token; naturally generates a continuation.Complete a prompt or write text.
Encoder–decoder (T5, BART)Encoder reads the input; decoder generates a new sequence while conditioned on it.Translate, summarize, or turn a table into text.

Which family fits?

Select a task, then explain why the input and output shapes suggest that family.

Encoder only: Read the whole supplied sentence and output one label. Both earlier and later words can help interpret a token.
Useful nuance: These are typical designs and training objectives. An encoder-only model is not the usual choice for fluent left-to-right generation, but “cannot generate text” is too absolute outside the lecture’s simplified comparison.
Exam rehearsal

7. Short essays and light calculations

Try to answer before opening each explanation. For a short essay, define the term, show one step or example, and state a tradeoff.

Why might web-scale data still produce an uneven model?

The web is large but its contributors are not a balanced sample of all languages, populations, or topics. Filtering can improve quality while changing coverage. A model learns patterns in the resulting corpus, so collection and cleaning choices affect what it learns.

Explain tokenization and the role of token IDs.

Tokenization divides text into units such as words or subwords. A vocabulary maps each unit to an integer ID so the model can look up its embedding. IDs identify units; the numeric distance between IDs is not a semantic distance.

Run the lecture’s BPE example: what happens after merging t+h, th+e, and c+a for “the cat”?

Start with [t,h,e,c,a,t]. Merge t+h → [th,e,c,a,t]. Merge th+e → [the,c,a,t]. Merge c+a → [the,ca,t]. The lecture also lists an a+t merge across the corpus, but the “the cat” sequence stays [the,ca,t] in that selected order.

If one tokenizer uses 9 tokens and another uses 4, what percentage fewer tokens are used?

(9 − 4) / 9 × 100 = 55.6%\((9-4)/9\times100\approx55.6\%\) fewer tokens for that particular string. The new token count is 4/9 ≈ 44.4%\(4/9\approx44.4\%\) of the old count.

A vocabulary has 5,000 IDs and embedding dimension 128. Give the table shape, entry count, and output shape for 6 tokens.

Table shape: 5,000 × 128\(5{,}000\times128\). Entry count: 640,000. The 6-token input yields 6 vectors, or a 6 × 128\(6\times128\) array when tokens are rows.

How does a contextual embedding differ from a static embedding?

A static lookup assigns a token the same starting vector each time. A contextual representation is calculated after considering surrounding tokens, so “bank” can have different final vectors in “bank account” and “river bank.”

Compare encoder-only, decoder-only, and encoder–decoder models using one task each.

An encoder-only model reads an available input bidirectionally for a task such as sentiment classification. A decoder-only model uses prior tokens to generate a completion. An encoder–decoder model reads an input and generates a separate sequence, such as a translation.

What does the sequence probability equation say in plain language?

It says the probability of a complete sequence can be written as a product of conditional probabilities: first token, then second given the first, then third given the first two, and so on. Decoder-style generation follows this order when extending a prompt.
