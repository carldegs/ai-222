Introduction

What does a Transformer do?

Consider “The cat opened its eyes.” To interpret “its,” we need information from “cat.” A Transformer is a neural network architecture that lets each position in a sequence gather information from other positions. Its central operation, attention, calculates how much information to take from each permitted position and combines that information into a new representation.

Look at the overview in slide 2. The diagram contains two main operations: attention lets positions exchange information, and a feed-forward network transforms the resulting features at each position. Slide 7 makes the first operation visual: thicker connections mean a larger contribution to a token’s updated representation. We will start with the input vectors, work through one attention calculation, and then return to the full block. The goal is to understand what each box does and why it is there.

The question for this lecture: How do we turn a sequence of starting vectors into representations that reflect the surrounding context?
Recap · RNNs

Two ways to carry context

Recall the recurrent model: it reads a sequence step by step, updating a hidden state that carries information forward. To bring an early word into a much later prediction, that information must pass through the intervening state updates. This is the specific connection we need from the previous lecture.

Attention gives us a different route. Within one layer, a position can combine information directly from any position it is allowed to use. During training, many positions can be processed in parallel; generating a continuation still proceeds token by token. Two consequences will matter below: we must supply position information explicitly, and full attention requires comparisons between pairs of tokens.

Start with the shape

Tokens become vectors

Let’s begin with what goes into the diagram. A token is a unit of text, often a word or word piece. The model represents each token with a learned list of numbers called an embedding vector. In slide 4, “cat opened its” gives us three tokens, each shown as a four-number vector. Stack those vectors as rows and we get a matrix: one row per token, one column per feature. Slide 5 separates these two dimensions: n\(n\) counts tokens, while d\(d\) is the width of each vector. We write the input as X ∈ Rⁿˣᵈ\(X\in\mathbb{R}^{n\times d}\).

Now look at slide 6. The output still has a vector at each position, but that vector can incorporate information from the surrounding tokens. We call it a contextualized representation. Attention is the operation that allows this exchange.

Shape check: three tokens with four features each means the input matrix is 3 × 4. The same word can acquire a different contextual output when surrounding words change.
Core computation

Query, key, value: choose what matters

How does a position choose which information to gather? Slides 8 and 11 introduce three learned projections of the input: the query, key, and value. A projection multiplies a vector by a learned weight matrix to create another vector. Think of the query as what a position is looking for, a key as what another position offers for comparison, and a value as the information that position can contribute. These are roles within the calculation; all three come from the input vectors in self-attention.

Q = XW_Q, K = XW_K, V = XW_V Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V
\[Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V\]\[\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\mathsf{T}}{\sqrt{d_k}}\right)V\]

Read the equation from left to right. First, QKᵀ computes a dot-product score for each query–key pair. A larger score indicates a stronger match under the learned projections. After scaling, softmax turns each query’s row of scores into weights across the keys. Those weights are nonnegative and add to 1. Finally, multiplying by V blends the value vectors using those weights. Slide 12 shows the pairwise comparisons as a matrix. Dividing by √dₖ\(\sqrt{d_k}\) keeps dot-product scores from becoming overly large as vector width grows.

Work one query row

Let’s make the equation concrete with just one query and two keys. We will use one-number values so we can see the final weighted sum easily. Suppose the query is q = [1, 0]\(q=[1,0]\), two keys are k₁ = [1, 0], k₂ = [0, 1]\(k_1=[1,0],\ k_2=[0,1]\), and their scalar values are 10 and 2.

1

Dot products: 1 and 0.

2

Scale by √2\(\sqrt 2\): scores become about 0.707 and 0.

3

Softmax: weights are about 0.670 and 0.330.

4

Blend values: 0.670(10) + 0.330(2) ≈ 7.36\(0.670(10)+0.330(2)\approx 7.36\).

Try it: If attention weights are already supplied, multiply each value by its weight and add. If raw scores are supplied, first scale them and apply softmax.

Reveal the pipeline one step at a time

For one token, use query q = [1, 0]. The two keys are k₁ = [1, 0] and k₂ = [0, 1]; their values are 10 and 2. Learned matrices produce queries, keys, and values from input vectors.
What the output means: Each token receives a new vector that blends information from tokens it was allowed to attend to. The blend changes when queries and keys change.
More than one comparison pattern

Why multiple attention heads?

One attention calculation gives us one pattern of connections. But a token can need several kinds of information at once. Multi-head attention runs several attention calculations with separate learned query, key, and value projections. Each head can therefore produce a different pattern and a different blend of information. In slide 13, follow each head separately; in slide 15, watch their outputs join together. Concatenation places the head outputs side by side, and the output projection mixes their features back into the model’s working width.

headᵢ = Attention(XWᵢᴽ, XWᵢᴷ, XWᵢⱽ) MultiHead(X) = concat(head₁, …, headₕ) Wᴼ
\[\mathrm{head}_i=\operatorname{Attention}(XW_i^Q,XW_i^K,XW_i^V)\]\[\operatorname{MultiHead}(X)=\operatorname{concat}(\mathrm{head}_1,\ldots,\mathrm{head}_h)W^O\]
Light shape example: With model width 8 and two heads of width 4, each head returns n × 4\(n\times4\). Concatenation returns n × 8\(n\times8\) before the final projection.
Order matters

How does a Transformer know token order?

We now have a way to compare token content, but where did we tell it which token came first? Attention by itself does not provide an absolute sequence order. Yet “the cat chased the dog” and “the dog chased the cat” use similar words to say different things. In slide 16, we supply order by adding a positional vector to each token embedding before it enters the blocks. The token vector carries content; the positional vector supplies information about where it occurs.

input at position i = token embedding xᵢ + positional vector pᵢ Both vectors must have the same width.
\[\widehat{x}_i=x_i+p_i\qquad (x_i,p_i\in\mathbb{R}^{d})\]

Slide 17 constructs positional vectors with sine and cosine functions at different frequencies. You do not need to calculate every coordinate to read the diagram: each position receives a vector of the same width as its embedding, so the two can be added. Learned positions and rotary positional embeddings are other ways to supply position information; we will return to the rotary version near the end.

Put the pieces together: Self-attention relates token content. Position information distinguishes the order in which those tokens occur. The positional vector is added to the embedding before it enters the block.
Inside an encoder block

What happens after attention?

Let’s return to the block diagram, now that attention is familiar. Attention mixes information between positions. The next operation, a feed-forward network, transforms the features within each position. It applies the same small neural network to every token vector: a linear transformation, a nonlinear activation such as ReLU or GELU, and another linear transformation. Slide 22 shows these operations. The weights are shared across positions, but each position supplies its own input vector.

FFN(x) = activation(xW₁ + b₁)W₂ + b₂
\[\operatorname{FFN}(x)=\phi(xW_1+b_1)W_2+b_2\]

Now follow the arrows that go around the sublayers in slide 20. These are residual connections: each adds a sublayer’s input back to its output. The layer can learn a change to the existing representation while keeping a direct path for information and gradients through the stack. Layer normalization recenters and rescales the features within a token's vector, making the scale of activations more stable. Unlike batch normalization, it does not need statistics from other examples in the batch. The lecture's block picture shows these operations around both attention and the feed-forward sublayer; their exact order can differ among Transformer variants.

Whole architecture

Encoder, decoder, and the future mask

We can now assemble the full encoder–decoder Transformer shown in slide 23. The encoder stacks blocks to turn the supplied input into contextual vectors. The decoder builds an output sequence, such as a translation, using the output prefix and the encoder’s representations. It first applies masked self-attention to the output prefix, then cross-attention to the encoder outputs. In cross-attention, the decoder supplies the queries and the encoder supplies the keys and values. A final linear projection produces scores over the vocabulary, and softmax converts those scores into next-token probabilities.

Why does slide 24 add a mask? During training, we may have the full target sentence available, but a prediction must use only the information it would have when generating. If a position could read the later answer token, it could bypass the prediction task. A causal mask blocks those future output positions. The table below separates the three attention operations by what each can see.

PartWhat it may attend toWhy it exists
Encoder self-attentionInput tokens, typically in both directionsBuild context-aware input representations
Masked decoder self-attentionCurrent and earlier output positionsPrevent future-token leakage during training and generation
Encoder–decoder attentionEncoder outputsLet generated output consult the input
Masking detail: Disallowed future positions receive an effectively −∞\(-\infty\) score before softmax, so their attention weight becomes zero. The mask controls visibility; it does not erase token embeddings.
Trace one prediction: Embed source tokens and add positions → encode the source → embed the target prefix and add positions → masked decoder attention → cross-attention to the source → vocabulary scores.
Where the design extends

Images, efficient attention, and other positions

The remaining slides show how this design extends. For an image, we can divide the pixels into patches and represent each patch as a token. Attention can then connect parts of the image just as it connects positions in text. Slide 26 compares this with a CNN: local filters and shared weights build in assumptions about nearby pixels. Those assumptions are an inductive bias. A vision Transformer supplies fewer of these image-specific assumptions, making the data and training setup especially important.

Next, slide 28 asks how to compute attention efficiently. Full attention compares every query with every key, giving a score matrix with n²\(n^2\) entries for n\(n\) tokens. FlashAttention reorganizes the exact attention calculation to reduce memory traffic; it does not change which tokens may attend to which. Finally, slide 29 revisits how we supply order. Rotary positional embedding (RoPE) encodes position by rotating pairs of query and key features, so their dot product can reflect relative position. These are refinements of the attention mechanism, not new definitions of a Transformer.

Check your understanding

Practice

Let’s put the lecture back together: tokens become vectors, position information supplies order, attention blends information across positions, and the feed-forward network transforms each result. Stacking these operations gives us an encoder or decoder. Try the questions below before opening the answers; for each one, explain the operation and what it changes.

1. Compare an RNN with a Transformer for long sequences.

An RNN passes information step by step through a hidden state. A Transformer’s attention can connect distant positions directly and process sequence positions in parallel. Full self-attention also requires a token-pair score matrix, which grows quadratically with sequence length; position information must be supplied.

2. If the input is 5 × 8 and the query projection is 8 × 4, what shape are the queries? How many attention scores arise with five keys?

The query matrix is 5 × 4: one four-feature query per token. Comparing five queries with five keys gives a 5 × 5 score matrix, or 25 scores.

3. Two values are 4 and 10, with attention weights 0.25 and 0.75. What is the output?

Take the weighted sum: 0.25(4) + 0.75(10) = 1 + 7.5 = 8.5. The weights sum to 1.

4. Explain query, key, and value without calling them separate sentences.

They are learned projections of the input vectors. A query is compared with keys to calculate attention weights; those weights blend the values into a contextual output.

5. Why scale dot-product scores?

Larger query/key dimensions can lead to larger dot products. Dividing by √dₖ\(\sqrt{d_k}\) moderates their magnitude so softmax is less likely to become extremely peaked, which helps learning.

6. What do multiple heads contribute?

Separate learned projections let different heads form different attention patterns. Their outputs are concatenated and linearly projected into the block’s output representation.

7. Why does a decoder need a causal mask?

When predicting the next token, a position must not access future output tokens. The mask makes those future attention weights zero, so training matches the information available during generation.

8. Distinguish encoder self-attention from encoder–decoder attention.

Encoder self-attention compares positions within the input. Encoder–decoder attention lets a decoder position query representations from the encoder, bringing source context into output generation.
