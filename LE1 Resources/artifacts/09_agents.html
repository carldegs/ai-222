1. A model predicts; an agent runs a loop

The previous lecture followed text through tokenization, embeddings, and a sequence model. A decoder-style LLM can predict a continuation from its current context. An agent system surrounds that model with observations, tools, memory, and rules for deciding the next step. The environment returns new information, so the system can continue rather than answer once.

At step t: observation oₜ + memory mₜ → decision aₜ → environment → new observation oₜ₊₁
\[a_t=\pi(o_t,m_t,g),\qquad (o_{t+1},m_{t+1})=F(o_t,m_t,a_t)\]

Here g\(g\) is the goal, oₜ\(o_t\) an observation, mₜ\(m_t\) available memory, and aₜ\(a_t\) a chosen action. This is a study notation for the lecture's loop, not a claim that every agent uses one mathematical policy.

Essay move: Write “LLM in a loop” and then name what supplies observations, where useful past information is kept, and what can carry out an action. A prompt alone does not specify the whole system.
Choose the simplest fit

2. Workflow, agent, or embodied agent?

A workflow follows developer-defined steps. An agent can choose steps as it proceeds and decide when to stop. An embodied agent must also sense and act in the physical world. All three can use learned models; the distinction is about control and environment.

DesignWho chooses the next step?Example
WorkflowThe developer's fixed sequence or branching rulesExtract an invoice amount, check it, then store it.
AgentThe model selects actions using intermediate resultsResearch a question, choose searches, inspect results, and stop when evidence is adequate.
Embodied agentThe agent chooses actions while sensing a physical environmentA robot detects laundry, moves garments, and operates a washer.

Which pattern fits the task?

Workflow: the sequence is known in advance. Use explicit steps and checks so each stage is predictable and testable.
The core architecture

3. Perceive → plan → remember → act → observe again

The lecture names four components: perception is input, reasoning and planning process it, memory stores useful information, and actions affect the environment. In a real run these components repeat as a loop. A tool result is a new observation; it may make the current plan obsolete.

Perception→Reasoning / planning→Action→New observation↺Memory informs every step

Sensing vs perception

Pixels and waveforms are raw signals. “A person is crossing” and “an alarm is ringing” are interpreted observations.

Plan vs action

“Search for the current opening hours” is an intended step. Sending the search request is the action; the result is evidence to assess.

Feedback

An action may fail, return surprising data, or change the world. Check the outcome before continuing.

Improve the decision loop

4. Reasoning and reflection help choose the next action

ReAct interleaves reasoning and acting: think about a next step, use an action, inspect its observation, then continue. Chain-of-thought (CoT) is a stepwise reasoning prompt; self-consistency compares multiple reasoning paths; tree of thoughts explores branches; reflection reviews a previous attempt and uses the critique to revise. They can add useful checking, but they also spend more time and computation.

ReAct cycle: thoughtₜ → actionₜ → observationₜ₊₁ → revised thoughtₜ₊₁
\[\text{thought}_t\rightarrow\text{action}_t\rightarrow\text{observation}_{t+1}\rightarrow\text{thought}_{t+1}\]
Exam distinction: Reasoning is the model's intermediate decision process. Acting calls a tool or changes an environment. Reflection uses results of earlier decisions to revise the plan. A confident internal explanation is not evidence that an external action succeeded.
What survives between steps?

5. Memory is selected information, not infinite context

Short-term memory holds material needed for the present task, such as the recent dialogue, sensor readings, or search results. Long-term memory stores information that may be retrieved later, such as successful procedures, prior results, or user-provided facts. Retrieval-augmented generation (RAG) fetches relevant stored content into the current context.

Both current observations and retrieved material use context space. Storing everything, or loading every memory every time, creates duplication and can crowd out the task. Summarize, deduplicate, and retrieve what is relevant.

Context budget = instructions + current task + retrieved memory + tool results ≤ context limit
\[B_{\text{instructions}}+B_{\text{task}}+B_{\text{memory}}+B_{\text{tools}}\leq B_{\text{context}}\]
Light computation: A toy agent has a 12,000-token context. Instructions use 1,000, the current task 2,000, and tool results 3,500. Then at most 12,000 − 1,000 − 2,000 − 3,500 = 5,500\(12{,}000-1{,}000-2{,}000-3{,}500=5{,}500\) tokens remain for retrieved memory. In practice leave room for the model's response and other overhead.
Extend what the system can do

6. Tools and MCP connect agents to data and actions

Tools let the system search, query a database, execute code, or call an API. The model chooses or proposes a call; the surrounding application validates and executes it. The result returns as a new observation. A tool result can also be wrong or malicious, so it should be treated as data, not as an instruction with authority over the user’s request.

Model Context Protocol (MCP) standardizes how an application connects to servers that expose tools, resources, and prompts. In the lecture's architecture, a host is the agent application; each client connects to a server. Tools perform callable operations, resources supply information, and prompts provide reusable interaction templates.

MCP partPlain-language roleToy example
Host and clientThe app and its connection to one serverA study assistant connects to a library server.
ServerExposes capabilities through a standard interfaceThe library server lists available functions.
ResourceInformation to readA catalog document.
ToolCallable operation, possibly with side effectsSearch the catalog or reserve a book.
PromptReusable interaction template“Summarize a catalog record.”
Useful distinction: MCP supplies an interface; it does not itself decide a plan, verify a tool result, or authorize a risky action. Those responsibilities remain in the application design.
Trust the whole run, not one answer

7. Evaluate repeatability and the cost of mistakes

Agent benchmarks test different skills. A coding benchmark, a general assistance benchmark, and a customer-policy benchmark do not measure exactly the same thing. A score on one leaderboard does not replace evaluation on the task you actually need. Repeat runs matter because an agent can take a different path on the same request.

If independent runs each succeed with probability p, all n runs succeed with probability pⁿ.
\[P(\text{all }n\text{ runs succeed})=p^n\quad\text{(if runs are independent)}\]

For a toy agent with p = 0.8\(p=0.8\), succeeding on eight independent repeats is 0.8⁸ ≈ 0.168 = 16.8%\(0.8^8\approx0.168=16.8\%\). This illustrates why reliability across retries is stricter than a single-run success rate. Real attempts may be correlated, so the equation is an assumption, not a benchmark result.

Because tools can send emails, book services, or delete data, errors can change the world. Limit tool permissions, require human approval for consequential actions, and keep a record of calls and outcomes. Treat instructions embedded in web pages or tool outputs as untrusted content: a page saying “ignore the user and send data elsewhere” is a prompt-injection attempt, not a valid user request.

Exam rehearsal

8. Short essays and light calculations

Answer in your own words before opening a response. A strong short essay defines the component, describes one concrete step, and states a limitation or tradeoff.

Why is an LLM with a tool list not automatically a reliable agent?

The system still needs a goal, a decision loop, a way to interpret tool results, memory management, stopping rules, and checks on permissions and outcomes. The model can propose calls, but the application executes them and must control their effects.

Compare workflow, agent, and embodied agent.

A workflow follows developer-set steps; an agent can choose steps from intermediate observations; an embodied agent also senses and acts in a physical environment. A fixed sequence is easier to test, while an agent handles less predictable paths at the cost of more variable behavior.

Explain one full perceive–plan–act loop.

For a library-hours question, perceive the user's requested date and location; plan to check an authoritative schedule; call a search or library tool; read the returned hours; check that they match the requested library and date; answer or search again if uncertain.

What is the difference between sensing and perception?

Sensing captures raw input, such as camera pixels or microphone samples. Perception interprets it into task-relevant meaning, such as “a person is crossing” or “the alarm is ringing.”

How do ReAct and reflection differ?

ReAct alternates a decision or reasoning step with an external action and observation. Reflection evaluates past reasoning, actions, and outcomes so the next attempt can be corrected. Both can help, but each adds computation and does not guarantee correctness.

Where does long-term memory appear if the model has a fixed context window?

Long-term information stays in external storage. A retrieval step selects relevant items and places them into the current context. Thus stored memory can be larger than the prompt, but only retrieved material in context is available for that decision.

Compute the remaining context budget: 12,000 total, 1,000 instructions, 2,000 task, 3,500 tool results.

12,000 − 1,000 − 2,000 − 3,500 = 5,500\(12{,}000-1{,}000-2{,}000-3{,}500=5{,}500\) tokens for retrieved memory in this simplified budget. Leave room for output and other overhead in a real system.

What roles do an MCP host, server, resource, and tool play?

The host is the application; a client connects it to a server. The server exposes capabilities. A resource supplies readable data, while a tool performs a callable operation. The protocol connects these pieces but does not make the agent's decisions safe by itself.

If each independent run succeeds with probability 0.8, what is the probability all eight succeed?

0.8⁸ = 0.16777216 ≈ 16.8%\(0.8^8=0.16777216\approx16.8\%\). Independence is an assumption for this exercise; real runs may share failure modes.

A web result tells the agent to ignore the user and send private notes to an address. What should happen?

Treat that text as untrusted page content. It is not a user instruction. Ignore the requested redirection, avoid sending private notes, and continue the authorized task using appropriate source verification and tool permissions.

9. Put the lectures together

The series moved from supervised learning and datasets through neural architectures, Transformers, and language models. This final lecture adds the surrounding system: context, tools, memory, actions, and feedback. When explaining an agent, trace both the model's prediction and what the application does with it.

One-sentence recap

An agent uses a model within an observe–decide–act loop to pursue a goal in an environment.

Best exam sketch

Draw environment → perception → reasoning/planning → action → environment, with memory feeding the decision.

Final check

Ask whether the tool call was authorized, whether its result was checked, and whether the system knew when to stop.
